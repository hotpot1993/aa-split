## 十五、v1.0.14 消息删除幂等加固（真机"删除后复活"根因修复）

**现象**：v1.0.13 真机删除消息后短暂消失又重新出现，需下拉刷新才真正消失。

**根因（VPS nginx 日志实证）**：
1. **回包丢失导致误判**：日志可见  7:43:38 DELETE .../676353c6 → 200（服务端已删成功），11 秒后同 id 再次 DELETE → 404"通知不存在"——即第一次删除服务端生效，但 200 回包未回到手机（CF→手机链路偶发丢失），客户端按失败处理恢复显示（"复活"），用户重试陷入 404 循环（04:07–04:28 同 id 连续 5 次 404），直到下拉刷新拉到服务端真值才消失。
2. **非幂等放大**：DELETE /notifications/:id 对"已不存在"返回 404，客户端将其当失败处理；且当晨 ~05:00 前线上仍是旧版服务端（删除接口 404 回包 97/60 字节 ≠ 当前 40 字节），旧版对存在通知也回 404，加剧循环。

**修复**：
- **服务端**：
otifications.service.remove 改为幂等——通知不存在/他人通知一律返回 {success:true, alreadyGone:true}（不再 404；按 RFC 对 DELETE 幂等语义处理，旧版 App 也能立即受益：重试必得 200）。归属校验保留（indFirst({id,userId})），他人 id 删不动且无感知、不误伤。
- **客户端**（messages_screen.dart）：删除/清空异常后不再盲目恢复显示，新增 _serverConfirmGone() 复核——重拉服务端列表，目标已不在 → 视为成功保持隐藏（提示"已删除"）；仍在/复核失败 → 恢复显示并明确报错。覆盖丢包、404、旧服务端三类场景。
- 同步更新：e2e（幂等断言 + 他人删除不误伤校验）、单测（幂等返回值）、smoke-api.mjs（delete 步骤改期望 200+success，兼作部署守卫——旧版服务端会在此步失败）。
